# Story 1.2: Migrate WordPress content into content files

- Epic: Epic 1: Content and migration
- Status: review

## Story

As the site owner, I want all WordPress content imported into `content/` by a repeatable script, so that the new site starts with exactly the content of the old one.

## Acceptance criteria

1. `packages/migrator` (TypeScript, Vitest, `pnpm --filter migrator migrate`) reads the live site: REST API for projects, posts (→ articles), tags + project_tag (→ `tags`, merged by slug), media; rendered HTML of `/`, each `/project/<slug>/` and each `/article/<slug>/` for content the API lacks (profile/about, experience, technologies, what I do, education, certifications, contact, links; project features, technologies, demo/code URLs).
2. HTML → Markdown (e.g. `turndown`, fenced code with language when detectable); every record validated with the contracts Zod schemas before writing.
3. Media downloaded to `apps/web/public/uploads/` (original file names); covers and portrait referenced as `/uploads/<file>`; alt text required (derive from title when WP alt is empty).
4. Idempotent: entries matched by `legacyWpId` (files keyed by slug); a second run produces no diff (proven by a test that runs the loader twice on recorded fixtures, and by running it twice for real).
5. `content/settings/redirects.yml` contains 301s: `/wp-sitemap.xml` → `/sitemap.xml`, `/feed/` → `/feed.xml`; `content/settings/site.yml` gets `siteUrl: https://edgar-ferreira.com` and the live site description.
6. Unit tests for the transformers run on recorded WP JSON/HTML fixtures under `packages/migrator/fixtures/` (no network in tests).
7. The real migration is run and its output committed: 3 projects, 5 articles, all tags, profile, media; the content test passes on it; a short import report (counts per type) is written into Dev notes.

## Dev notes

### What was built

- `packages/migrator` (`@portfolio/migrator`): `source/` (WP REST + rendered pages, Zod-validated
  `Wp…` payloads; `fetchSnapshot` live, `readSnapshotDir` recorded), `html/` (cheerio extractors for the
  home page, project pages, article pages; Cloudflare email de-obfuscation), `markdown/` (turndown,
  ATX headings, `-` bullets, fenced code with the `language-x` class as fence language), `transform/`
  (`buildContentPlan`: pure, validates every record with the contracts schemas, throws `ValidationError`
  naming `collection/slug`), `serialize/` (`yaml` stringify, `lineWidth: 0`; frontmatter laid out like the
  e2e fixtures), `load/` (`writeContentPlan`: idempotent writer), `cli.ts`.
- `pnpm --filter migrator migrate [--from <snapshot dir>] [--base-url …]` runs through `tsx`.
- Tests (34, Vitest, tagged `[story 1.2]`) run only on recorded fixtures in `packages/migrator/fixtures/`
  (`rest/*.json` from `/wp-json/wp/v2/*` with `per_page=100`, `html/*.html` from `curl`). They were
  written first and failed on the missing modules before the implementation existed.
- Fixtures: HTML recorded with `curl`, then `<style>`, `<script>` and `<link>` tags stripped to keep them
  ~20 KB each (the theme inlines ~100 KB of CSS per page); `rest/root.json` was trimmed to
  `name`, `description`, `url`, `home`. `biome.jsonc` now ignores `packages/migrator/fixtures` so the
  recordings stay byte-for-byte.

### Decisions

- **Featured projects:** all 3 are `isFeatured: true`, derived from the live home carousel
  (`listFeaturedProjectSlugs`: every `/project/<slug>/` link in `[data-carousel]`); the live carousel
  shows all three. Change in Decap if fewer should be in the carousel.
- **Demo / code URLs:** every live project has `href="#"` on View Demo / View Code, so none were written.
- **Project tags** are ordered by term id (the live pages show "Golang • Kafka • Docker"); **article tags**
  by name (the live pages show them alphabetically).
- **Cover alt text:** WP `alt_text` is empty for every media item, so `coverImageAlt` = project title
  (the live theme does the same). `portraitAlt` = `Portrait of <name>` (the media title is just "profile").
- **Profile texts** come from the rendered home page; where the live wording differs from the CV mockup:
  education and certifications use "A (B)" instead of "A — B" (mockup + e2e fixture convention);
  experience `role` keeps only the part before " · " (the schema has no description field; the
  descriptions such as "ANTAQ: APEX apps for process management…" are dropped). Bio, languages and
  everything else are taken verbatim from the live site, not from the mockup's rewritten summary.
- **contact.email** = "Primary Email" (`efsn88@gmail.com`). The business email
  (`contato@edgar-ferreira.com`) is a contact link "Email (Business)". Emails were behind Cloudflare
  email obfuscation and are decoded (`decodeCloudflareEmail`).
- **Links:** hero and contact links merged into one list by URL (LinkedIn is in both), keeping the order of
  both lists. Icons are derived from labels.
- **site.yml description:** WordPress' tagline (`blogdescription`) is empty and the site has no meta
  description, so it is the first bio sentence without "Hello! I'm " (139 chars, max 160).
  `siteUrl` comes from the REST `home` field (`url` is `/wp` on Bedrock).
- **Code fences:** `language-plaintext` (and `text`/`none`) produce a fence without language.
- **Media:** all 6 library items are downloaded under their original file names, including the two
  favicons, which nothing references yet (story 2.1/3.1 may use them). Existing upload files are not
  re-downloaded (WP originals are immutable), which keeps re-runs offline for media.
- **Idempotency:** files are only written when their contents change; projects/articles are matched by
  `legacyWpId` across the folder, so a WP slug change replaces the old file; files without `legacyWpId`
  (hand-written) are never touched; existing redirects are kept and the two required ones added only if
  missing.
- `domhandler` (5.0.3, the version cheerio uses) is a dev dependency for its types only; the migrator
  tsconfig adds the `DOM` lib because turndown's API is typed with DOM nodes.

  kafka + golang", and the project summary says "This article presents…" (live content, kept as is).

  (capital F after a comma, live wording kept).
- The hero "Portfolio" link points to `https://github.com/zzedgat2012`, while the contact "Portfolio"
  link points to `https://edgar-ferreira.com`, and the hero "Email" is `edgar@serigy.net` (a third

- Some articles use numbered paragraphs (`<p>1. <strong>…</strong></p>`) rather than lists; turndown
  escapes them as `1\.` so they render as numbered paragraphs, exactly like the live site.
- No article has a cover image (`featured_media` 0).
