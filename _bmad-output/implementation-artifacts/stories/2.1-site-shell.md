# Story 2.1: Site shell: header, footer, layout, 404

- Epic: Epic 2: Pages
- Status: review

## Story

As a visitor, I want a consistent header, footer and not-found page, so that I can navigate the site from anywhere.

## Acceptance criteria

1. Header per mockups: "Edgar Ferreira" home link + nav `About`, `Projects`, `Articles`, `Contact` linking to `/#about` etc.; current section/page marked with `aria-current`; mobile layout per `Home — mobile`; a "Skip to content" link.
2. Footer: `© <year> Edgar Ferreira. All rights reserved.` (name from profile).
3. 404 page per `404 — desktop/mobile` mockups, served by Cloudflare for unknown URLs (`/404.html`), with a link home; returns HTTP 404 under `wrangler dev`.
4. `next.config.ts` has `trailingSlash: true` (D1); existing routes still pass.
5. Tokens only from `globals.css` `@theme` (DESIGN.md); `lucide-react` for icons; landmarks `banner`, `navigation`, `main`, `contentinfo`.
6. Playwright: nav links, skip link, 404 status and content, mobile viewport header.

## Dev notes

Implemented 2026-11-08 following AGENTS.md directly (`/bmad-build` not loadable: `uv` missing).

**TDD.** `e2e/shell/{header,footer,not-found}.spec.ts` (18 tests, `[story 2.1]`, critical path `@smoke`) were
written first and all failed on missing elements; Vitest specs for the pure nav/copyright model failed on
missing modules before the code existed. AC map: AC1 → header.spec (home link, nav hrefs, `aria-current`
from hash and after click, skip link, mobile menu open/close/Escape); AC2 → footer.spec; AC3 →
not-found.spec (HTTP 404 under `wrangler dev`, content, attempted path, Back to Home, Go Back,
suggestions, no script errors, mobile); AC4 → `next.config.ts` + every existing spec still green;
AC5 → landmarks test + `lucide-react` + `@theme` tokens; AC6 → all of the above.

**Decisions**
- Route group `app/(site)/layout.tsx` holds the shell (skip link, header, `<main id="main-content">`,
  footer). `app/not-found.tsx` sits outside the group, so the 404 renders **without** header/footer,
  as the `404 — desktop/mobile` mockups show (mockup wins for layout). It still has a `main` landmark
  and a link home. Pages inside `(site)` must not render their own `<main>`.
- `aria-current`: `page` on `/project/…` (Projects) and `/article/…` (Articles); `location` for the
  home section named in the URL hash (`/#contact`), updated on `hashchange`. Pure logic in
  `findCurrentNavItem` (Vitest). No scroll-spy yet: the home sections do not exist until story 2.2,
  which may add an IntersectionObserver feeding the same function.
- Nav links are plain `<a href="/#…">` (not `next/link`) so same-page hash navigation fires
  `hashchange` natively.
- Mobile (< md): one `<nav aria-label="Main">` whose list collapses behind a "Menu" button
  (`aria-expanded`, `aria-controls`, Escape closes and returns focus, choosing a link closes it);
  panel uses `background` at 95% with blur (DESIGN.md › Colors).
- Header name and footer owner both come from `getProfile().name`. Footer year = build year
  (static export; every publish rebuilds).
- 404 "Attempted path" and timestamp are read in the browser (client components) because the same
  `404.html` is served for every unknown URL. "Work" suggestion links to `/#experience` (D1 anchor;
  the mockup label has no other matching section).
- Tokens: added `--tracking-eyebrow: 0.8em` and `--tracking-meta: 0.35em` to `globals.css` `@theme`
  (both already in DESIGN.md typography) and a global `:focus-visible` ring (DESIGN.md `focus-ring`).
  No hex values or arbitrary sizes in components; the ghost "404" uses `text-9xl` + `scale-150/200`.
- `lucide-react` pinned to `1.59.0` (released 2026-10-17, i.e. not a days-old release).

**Deviations / notes for review**
- 404 without the site header (see above): flag to UX if the shell should appear there too.
- Header is not sticky; the mockup does not show scroll behavior.
- Footer divider placed above the notice (DESIGN.md divider rule); the desktop mockup draws a line
  through the bottom of the text, read as an export artifact.
