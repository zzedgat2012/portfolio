# Story 3.1: SEO, feeds and redirects

- Epic: Epic 3: SEO and launch
- Status: ready-for-dev

## Story

As the site owner, I want search engines and feed readers to find the new site exactly like the old one, so that no traffic is lost at cut-over.

## Acceptance criteria

1. Metadata per page: title template, description, canonical (`siteUrl` + path with trailing slash), Open Graph + Twitter card (cover/portrait image), `lang="en"`.
2. JSON-LD: `Person` on `/`, `Article` on articles, `CreativeWork` on projects.
3. `/sitemap.xml` lists `/`, every project and article URL (absolute, trailing slash, lastmod); `/robots.txt` allows all and points to the sitemap; `/cv/` excluded.
4. `/feed.xml`: RSS 2.0 of articles (title, link, guid, pubDate, description).
5. `out/_redirects` generated from `content/settings/redirects.yml` (D4); under `wrangler dev`, `/feed/` and `/wp-sitemap.xml` answer 301 to the new URLs.
6. A parity script `pnpm --filter web verify:parity <baseUrl>` fetches every URL of the old `wp-sitemap.xml` (recorded list committed in `apps/web/scripts/legacy-urls.txt`) against `<baseUrl>` and fails unless each answers 200 (or 301 to a 200).
7. Playwright specs for metadata, sitemap, robots, feed and redirects.
