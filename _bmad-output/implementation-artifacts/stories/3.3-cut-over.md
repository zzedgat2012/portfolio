# Story 3.3: Cut-over

- Epic: Epic 3: SEO and launch
- Status: ready-for-dev (blocked on owner: DNS changes need a person)

## Story

As the owner, I want `edgar-ferreira.com` and `www` served by the new site, so that WordPress can be retired without losing URLs.

## Acceptance criteria

1. `edgar-ferreira.com` and `www.edgar-ferreira.com` are custom domains of the `portfolio-web` Worker (D6).
2. `www` answers 301 to the apex.
3. `pnpm --filter web verify:parity https://edgar-ferreira.com` reports every legacy URL OK.
4. `ALLOWED_ORIGINS` of `portfolio-decap-auth` lists only `https://edgar-ferreira.com`; the Decap login works at `https://edgar-ferreira.com/admin/`.
5. Rollback is documented and was not needed (or was tested).

## Runbook

Run from the repo root. `export CLOUDFLARE_ACCOUNT_ID=86dd3c836ae52e572ce13a51e3d63390`. Zone id: `c09091eac2562f727b88e17f2074867f`.

### Back up the DNS records

```bash
cf dns records list -z c09091eac2562f727b88e17f2074867f > dns-backup.json
```

The records to remove, as of 2026-11-09:

| id | type | name | content | proxied |
| --- | --- | --- | --- | --- |
| bbdfadc5457cb96b1fa0e38e579bc765 | CNAME | edgar-ferreira.com | 3d951e0e-fd56-45fe-b516-5b66809d014d.cfargotunnel.com | yes |
| df6056564539911d69c04507c76b6c7e | CNAME | www.edgar-ferreira.com | 3d951e0e-fd56-45fe-b516-5b66809d014d.cfargotunnel.com | yes |

Leave the MX, SPF and DKIM records, the `*` A record and the `auth` record alone.

### Point the web Worker at the domains

In `apps/web/wrangler.jsonc`, replace the "Until cut-over" comment and `"workers_dev": true` with:

```jsonc
"routes": [
  { "pattern": "edgar-ferreira.com", "custom_domain": true },
  { "pattern": "www.edgar-ferreira.com", "custom_domain": true }
],
"workers_dev": false,
"preview_urls": false,
```

### Switch over

Downtime is the few seconds between the delete and the deploy.

```bash
cf dns records delete bbdfadc5457cb96b1fa0e38e579bc765 -z c09091eac2562f727b88e17f2074867f
cf dns records delete df6056564539911d69c04507c76b6c7e -z c09091eac2562f727b88e17f2074867f
pnpm --filter web run deploy
```

### Redirect www to the apex

In the dashboard, open Rules › Redirect Rules › Create:

- Match: hostname equals `www.edgar-ferreira.com`.
- Action: dynamic redirect to `concat("https://edgar-ferreira.com", http.request.uri.path)`, status 301, preserve query string.

You can do the same with the API (`cf rulesets rules create`) in the `http_request_dynamic_redirect` phase.

### Check

```bash
pnpm --filter web verify:parity https://edgar-ferreira.com
curl -sI https://www.edgar-ferreira.com/project/ecommerce-platform/   # expect 301 to the apex
```

### Close the preview origin

In `apps/decap-auth/wrangler.jsonc`, set `ALLOWED_ORIGINS` to `"https://edgar-ferreira.com"`. Then:

```bash
pnpm --filter decap-auth run deploy
```

Log in at https://edgar-ferreira.com/admin/.

### Commit

```bash
git commit -am "chore(web): serve edgar-ferreira.com from Workers (story 3.3)"

```

### Rollback

1. Remove `routes` from `apps/web/wrangler.jsonc`, set `workers_dev: true`, then run `pnpm --filter web run deploy`. This detaches the custom domains.
2. Recreate both CNAMEs to `3d951e0e-fd56-45fe-b516-5b66809d014d.cfargotunnel.com`, proxied:

   ```bash
   cf dns records create -z c09091eac2562f727b88e17f2074867f --type CNAME --name edgar-ferreira.com --content 3d951e0e-fd56-45fe-b516-5b66809d014d.cfargotunnel.com --proxied
   cf dns records create -z c09091eac2562f727b88e17f2074867f --type CNAME --name www --content 3d951e0e-fd56-45fe-b516-5b66809d014d.cfargotunnel.com --proxied
   ```

   Check the exact flags with `cf dns records create --help`.
