# Story 1.1: Content model for the whole site

- Epic: Epic 1: Content and migration
- Status: review

## Story

As the editor, I want every kind of site content defined in Decap and validated in code, so that I can edit all of it and the build rejects broken content.

## Acceptance criteria

1. `config.yml` and `packages/contracts` define the collections in architecture D2 (`projects`, `articles`, `tags`, `settings/site` + `siteUrl`, `settings/profile`, `settings/redirects`), with the listed fields, validation and Decap widgets (relation widgets for tags; list/object widgets for profile groups; `hidden` for `legacyWpId`).
2. `contentModel` registers every collection; the parity test passes for all of them (fields and required-ness).
3. The content test also fails when a relation (project/article `tags`) points to a missing tag, with the file and slug in the message.
4. Domain models + mappers exist for Project, Article, Tag, Profile, SiteSettings (with `siteUrl`), Redirect; mappers resolve tag slugs to `{slug,name}`, drop `legacyWpId`, compute article reading time (ceil(words/200)).
5. Query functions: `listProjects` (sortOrder asc), `getProjectBySlug`, `listFeaturedProjects`, `listArticles` (publishedOn desc), `getArticleBySlug`, `getProfile`, `listRedirects`; unit-tested against fixture content.
6. `apps/web/e2e/content` holds fixture entries for every collection (`seed-…` slugs: 2 projects, 2 articles, their tags, profile, redirects) and `content/` holds valid placeholder files where a file collection is required (real content arrives in 1.2).
7. Existing specs stay green.

**Decisions / deviations**
- Parity test extended: ignores the `body` field of `md` folders (it is the Markdown body, not frontmatter) and
  asserts it is a `markdown` widget; compares nested object/list `fields` (names + required-ness) recursively;
  checks relation widgets (`value_field: "{{slug}}"`) and that `legacyWpId` is `hidden`.
- Relation integrity: `listBrokenRelations(model, entries)` in contracts (so the migrator can reuse it); the content
  test runs it on `content/` and `e2e/content`, messages look like
  `projects/p.md: tags references "kafka", which is not in tags`. Mappers also throw `ValidationError` on an unknown tag.
- Optional/required: project/article `tags`, project `technologies`/`features`, profile `education`/`certifications`,
  `redirects`, `isFeatured`, link `showInHero`/`showInContact` default in Zod (`[]` / `false`) and are
  `required: false` in Decap. Profile `technologies`, `whatIDo`, `experience`, `links` are required non-empty (`min: 1`).
- Extra validation beyond D2: article `coverImageAlt` required when `coverImage` is set; experience `endOn >= startOn`;
  redirects: unique `from`, `from !== to`, status 301|302 (Decap number widget, int, 301..302); `siteUrl` is an
  http(s) origin without trailing slash; link `url` http(s)/mailto:/tel:; link `icon` from `LINK_ICONS`
  (portfolio, website, linkedin, github, email, phone, whatsapp, facebook, instagram, twitter).
- Reading time is `max(1, ceil(words/200))` (an empty body still reads as 1 min).
- Placeholders in `content/`: `settings/site.yml` got `siteUrl: https://edgar-ferreira.com`; `settings/redirects.yml`
  already holds the two 301s from story 1.2 AC5; `settings/profile.yml` is a minimal valid placeholder that the
  migrator overwrites. No `projects/`, `articles/`, `tags/` folders yet (empty is valid).
- Fixture images (`/uploads/seed-*.png`) are referenced but not created; pages stories (2.x) must add them (or
  adjust the fixtures) if they render the images.
- Vitest (`apps/web`): `vitest.setup.ts` mocks `server-only`; `CONTENT_DIR` points at `e2e/content`, so query tests
  read the fixtures.
- `SLUG_PATTERN` is now exported from `packages/contracts/src/branded.ts` (internal, not in the package index).
- `external/` not read. No new dependencies.
